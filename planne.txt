============================================================

PROJECT IDEA
------------

StatAgent is an autonomous data investigation system.

The user provides:

1. A dataset
2. A business/data-related question

The system then:

1. Understands the question
2. Profiles the dataset
3. Creates an investigation plan
4. Decides which analysis is appropriate
5. Runs statistical analysis using Python
6. Validates the evidence
7. Produces an analytical report

The main principle of the project is:

    LLM decides WHAT to do
    Python decides/calculates the ACTUAL RESULTS
    LLM interprets the RESULTS

This separation is important because an LLM should not be trusted
to perform numerical/statistical calculations itself.

============================================================
WHY DO WE NEED AGENTS?
============================================================

A normal data analysis program follows a fixed workflow.

For example:

Load data
   ↓
Calculate mean
   ↓
Calculate correlation
   ↓
Generate report

The problem is that every question requires a different analysis.

For example:

Question 1:
"Which factors are associated with survival?"

Possible analysis:
- Group comparison
- Chi-square test
- Correlation
- Statistical testing

Question 2:
"Is income related to spending?"

Possible analysis:
- Correlation
- Regression
- Group analysis

Question 3:
"Does one group spend more than another?"

Possible analysis:
- Group analysis
- T-test
- Mann-Whitney U test

Therefore, we need an intelligent system that decides what
analysis should be performed.

That is where the agents come in.


============================================================
COMPONENT 1 — AGENT STATE
============================================================

File:

graph/state.py


Purpose:

The AgentState acts as the shared memory of the entire
LangGraph workflow.

Instead of every agent maintaining its own separate variables,
all agents can read and update the same state.


The state contains:

question
    The user's analytical question.

dataset_path
    Location of the dataset.

dataset_profile
    Information about the dataset.

investigation_plan
    Tasks created by the Planner Agent.

current_task
    Task currently being investigated.

completed_tasks
    Tasks that have already been completed.

analysis_results
    Results returned by statistical tools.

generated_code
    Code generated for flexible analysis.

execution_error
    Error generated during code execution.

critic_feedback
    Feedback from the validation/critic stage.

evidence_sufficient
    Whether enough evidence exists to answer the question.

final_report
    Final response generated for the user.

iteration
    Number of investigation iterations.


The state uses:

TypedDict

This provides a structured definition of what information can
exist inside the state.


Why total=False?

Because all information does not exist at the beginning.

For example:

At the beginning:

question = available
dataset_path = available

But:

analysis_results
final_report
critic_feedback

may not exist yet.

Therefore, total=False allows fields to be added gradually.


IMPORTANT CONCEPT:

AgentState can be thought of as the agent's investigation notebook.

Every node in LangGraph can read information from it and update it.


============================================================
COMPONENT 2 — DATASET PROFILER
============================================================

File:

tools/profiler.py


Purpose:

The profiler extracts factual information about the dataset.

The LLM should not guess information about the dataset.

Therefore, Python performs the profiling.


The profiler identifies:

1. Number of rows
2. Number of columns
3. Column names
4. Numerical columns
5. Categorical columns
6. Missing values
7. Duplicate rows
8. Descriptive statistics


Example:

Dataset:

PassengerId | Age | Sex | Fare | Survived

The profiler can produce:

Rows:
891

Columns:
5

Numerical:
Age
Fare
Survived
PassengerId

Categorical:
Sex

Missing values:
Age -> 177

etc.


IMPORTANT PRINCIPLE:

Dataset facts should come from Python,
not from the LLM.


Why?

Because an LLM may hallucinate a column.

For example, if the dataset contains:

Age
Sex
Fare

The LLM might incorrectly assume:

Income

exists.

The profiler gives the LLM the actual schema.


============================================================
COMPONENT 3 — PLANNER AGENT
============================================================

File:

agents/planner.py


Purpose:

The Planner Agent converts the user's analytical question
into a sequence of investigation tasks.


Input:

1. User question
2. Dataset profile


Output:

Investigation plan


Example question:

"What factors are associated with passenger survival?"


Planner might generate:

1. Check missing values and data quality.
2. Compare survival rates across categorical variables.
3. Test association between Sex and Survival.
4. Compare Age between survived and non-survived passengers.
5. Analyze the relationship between Fare and Survival.
6. Summarize statistically supported findings.


The Planner does NOT perform the analysis.

It only decides:

WHAT should be investigated?


This separation makes the architecture cleaner.


============================================================
PLANNER PROMPT
============================================================

The Planner is instructed to:

- Create a clear investigation plan.
- Use only available dataset columns.
- Avoid inventing columns.
- Break complex questions into smaller tasks.
- Prefer statistical/data-driven investigations.
- Avoid unnecessary analysis.
- Return numbered investigation tasks.


The Planner receives:

User Question
+
Dataset Profile


and produces:

Investigation Plan


============================================================
WHY DOES THE PLANNER NEED THE DATASET PROFILE?
============================================================

Without the dataset profile, the LLM does not know the available
variables.

Example:

Question:

"What factors affect salary?"

But the dataset contains:

Age
Gender
Department
Experience

and does NOT contain Salary.

A naive LLM might still generate:

"Calculate correlation between experience and salary."

This is invalid.

By giving the dataset profile to the Planner, it can recognize
that Salary is unavailable.


Therefore:

Dataset Profiler
        ↓
Dataset facts
        ↓
Planner


This reduces hallucination.


============================================================
LLM MODEL
============================================================

Current model:

openai/gpt-oss-120b

Provider:

Groq


Temperature:

0


Why temperature = 0?

We want predictable and consistent analytical planning.

The system is not being used for creative writing.

We want:

same question
+
same dataset
=
similar analytical plan


rather than highly random outputs.

tools/statistics.py


Purpose:

1. Descriptive Statistics

3. Correlation Analysis

============================================================
1. DESCRIPTIVE STATISTICS
============================================================

Function:

descriptive_statistics()


Purpose:

Summarize a numerical variable.


It calculates:

Count
Mean
Median
Standard deviation
Minimum
Maximum
Q1
Q3


Example:

Age:

Mean = 29.7
Median = 28
Std = 14.5
Min = 0.4
Max = 80


Why do we need it?

Before performing advanced analysis, we need to understand
the basic distribution of the data.


============================================================
2. GROUP ANALYSIS
============================================================

Function:

group_analysis()


Purpose:

Compare a numerical variable across groups.


Example:

Compare:

Fare

across:

Sex


Output can contain:

Group
Count
Mean
Median


Example:

Male:
Mean Fare = X

Female:
Mean Fare = Y


This gives a simple group-level comparison.


============================================================
3. CORRELATION ANALYSIS
============================================================

Function:

correlation_analysis()


Supports:

Pearson correlation
Spearman correlation


Pearson:

Measures linear relationship between numerical variables.


Spearman:

Measures monotonic relationship and is based on ranks.


Output:

Correlation coefficient
P-value
Sample size


Example:

Age vs Fare

correlation = 0.096

p_value = ...


IMPORTANT:

Correlation does NOT automatically mean causation.


============================================================
4. HYPOTHESIS TESTING
============================================================

Function:

hypothesis_test()


Currently supports:

Chi-square
Independent t-test
Mann-Whitney U test


------------------------------------------------------------
CHI-SQUARE TEST
------------------------------------------------------------

Used mainly to test association between categorical variables.


Example:

Sex
vs
Survived


Question:

"Is passenger sex associated with survival?"


The tool creates a contingency table and performs:

Chi-square test


Output:

Test statistic
p-value
Degrees of freedom
Sample size


------------------------------------------------------------
T-TEST
------------------------------------------------------------

Used to compare the means of two groups.


Example:

Age

between:

Survived
Not Survived


The implementation uses:

Independent two-sample t-test

with:

equal_var=False


This corresponds to Welch's t-test.


------------------------------------------------------------
MANN-WHITNEY U TEST
------------------------------------------------------------

Non-parametric alternative for comparing two independent groups.


Useful when assumptions for a t-test are not appropriate.


The implementation performs a two-sided test.


============================================================
WHY USE SCIPY?
============================================================

We could ask the LLM to calculate statistics.

That would be a bad design.

For example:

LLM:
"Correlation = 0.73"

But the actual value could be:

0.42

The LLM is not a calculator.

Therefore:

LLM
↓
Decision

Python + SciPy
↓
Calculation

LLM
↓
Interpretation


This is one of the most important design principles of StatAgent.

The Investigator determines:

Columns:
Sex
Survived

Test:
chi-square


Reason:

IMPORTANT:

The Investigator currently DOES NOT calculate the result.

============================================================
WHY NOT USE LLM-GENERATED PYTHON FOR EVERYTHING?
============================================================

One possible architecture is:

LLM
 ↓
Generate Python code
 ↓
Execute code
 ↓
Result


This is flexible but introduces additional risks:

- Invalid code
- Wrong columns
- Incorrect statistical methods
- Runtime errors
- Security concerns
- Harder debugging


Our current architecture is safer and simpler:

LLM selects from controlled statistical tools.


This is called a controlled-tool approach.


Later, we can introduce a Python executor for analyses that
cannot be handled by the predefined tools.


============================================================
CONTROLLED TOOLS VS FLEXIBLE PYTHON
============================================================

Controlled tools:

Advantages:

- Safer
- Easier to debug
- Predictable
- Easier to validate
- Easier to explain in interviews


Flexible Python executor:

Advantages:

- Much more flexible
- Can handle unusual analytical questions
- Can generate custom visualizations
- Can perform analyses not covered by predefined tools


StatAgent will start with controlled tools.

A Python executor already exists in the planned architecture,
but it will only be used when necessary.


============================================================
IMPORTANT DESIGN PRINCIPLE
============================================================

Never let the LLM invent statistical results.


Correct:

LLM:
"Use chi-square."

Python:
"Chi-square statistic = X,
p-value = Y."

LLM:
"The result provides evidence about association..."


Incorrect:

LLM:
"Chi-square statistic = X."

when Python never calculated X.


The actual evidence must come from deterministic tools.


============================================================
ERROR HANDLING
============================================================

The statistical functions contain validation checks.

Example:

If a requested column does not exist:

ValueError:
Column 'Income' not found in dataset.


If a t-test is requested but the grouping column contains
more than two groups:

ValueError:
The grouping column must contain exactly two groups.


This is important because agents can make incorrect tool selections.


The future workflow can catch these errors and decide whether
another investigation is required.

============================================================
INTERVIEW QUESTIONS TO KNOW
============================================================

Q1. Why did you use LangGraph?

Answer:

I used LangGraph to manage the multi-step agent workflow and
shared state between different stages such as planning,
investigation, validation and reporting.


Q2. Why not let the LLM perform statistical calculations?

Answer:

LLMs are not reliable numerical calculators. I use the LLM for
reasoning and tool selection while Python and SciPy perform the
actual deterministic calculations.


Q3. Why do you need a dataset profiler?

Answer:

The profiler gives the agent factual information about the
dataset schema, data types, missing values and statistics.
This reduces the chance of the LLM inventing columns or making
unsupported assumptions.


Q4. What is the role of the Planner?

Answer:

The Planner converts the user's analytical question into a
sequence of smaller investigation tasks.


Q5. What is the role of the Investigator?

Answer:

The Investigator determines which statistical method or tool
is appropriate for the current investigation task.


Q6. Why separate Planner and Investigator?

Answer:

The Planner focuses on what should be investigated, while the
Investigator focuses on how a particular task should be analyzed.


Q7. Why use SciPy?

Answer:

SciPy provides reliable implementations of statistical tests
such as chi-square, t-test and Mann-Whitney U, so the numerical
results are calculated deterministically rather than generated
by the LLM.


Q8. What is the difference between Pearson and Spearman
correlation?

Answer:

Pearson measures linear association between numerical variables,
while Spearman measures monotonic association using ranked data.


Q9. What is the chi-square test used for?

Answer:

It can be used to test whether two categorical variables are
statistically associated.


Q10. Does correlation imply causation?

Answer:

No. Correlation indicates statistical association, not necessarily
a causal relationship.


Q11. Why use temperature 0?

Answer:

The agents are performing analytical planning and tool selection,
where predictable outputs are preferred over creative variation.


Q12. What is AgentState?

Answer:

AgentState is the shared memory structure of the LangGraph
workflow. It stores information such as the user question,
dataset profile, investigation tasks, analysis results and
final report.
