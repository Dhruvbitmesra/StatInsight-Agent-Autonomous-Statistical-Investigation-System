============================================================

PROJECT IDEA
------------

StatAgent is an autonomous data investigation system.

The user provides:

1. A dataset
2. A business/data-related question

The system then:

1. Understands the question
2. Profiles the dataset
3. Creates an investigation plan
4. Decides which analysis is appropriate
5. Runs statistical analysis using Python
6. Validates the evidence
7. Produces an analytical report

The main principle of the project is:

    LLM decides WHAT to do
    Python decides/calculates the ACTUAL RESULTS
    LLM interprets the RESULTS

This separation is important because an LLM should not be trusted
to perform numerical/statistical calculations itself.

============================================================
WHY DO WE NEED AGENTS?
============================================================

A normal data analysis program follows a fixed workflow.

For example:

Load data
   ↓
Calculate mean
   ↓
Calculate correlation
   ↓
Generate report

The problem is that every question requires a different analysis.

For example:

Question 1:
"Which factors are associated with survival?"

Possible analysis:
- Group comparison
- Chi-square test
- Correlation
- Statistical testing

Question 2:
"Is income related to spending?"

Possible analysis:
- Correlation
- Regression
- Group analysis

Question 3:
"Does one group spend more than another?"

Possible analysis:
- Group analysis
- T-test
- Mann-Whitney U test

Therefore, we need an intelligent system that decides what
analysis should be performed.

That is where the agents come in.


============================================================
COMPONENT 1 — AGENT STATE
============================================================

File:

graph/state.py


Purpose:

The AgentState acts as the shared memory of the entire
LangGraph workflow.

Instead of every agent maintaining its own separate variables,
all agents can read and update the same state.


The state contains:

question
    The user's analytical question.

dataset_path
    Location of the dataset.

dataset_profile
    Information about the dataset.

investigation_plan
    Tasks created by the Planner Agent.

current_task
    Task currently being investigated.

completed_tasks
    Tasks that have already been completed.

analysis_results
    Results returned by statistical tools.

generated_code
    Code generated for flexible analysis.

execution_error
    Error generated during code execution.

critic_feedback
    Feedback from the validation/critic stage.

evidence_sufficient
    Whether enough evidence exists to answer the question.

final_report
    Final response generated for the user.

iteration
    Number of investigation iterations.


The state uses:

TypedDict

This provides a structured definition of what information can
exist inside the state.


Why total=False?

Because all information does not exist at the beginning.

For example:

At the beginning:

question = available
dataset_path = available

But:

analysis_results
final_report
critic_feedback

may not exist yet.

Therefore, total=False allows fields to be added gradually.


IMPORTANT CONCEPT:

AgentState can be thought of as the agent's investigation notebook.

Every node in LangGraph can read information from it and update it.

COMPONENT 2 — DATASET PROFILER
============================================================

File:

tools/profiler.py


Purpose:

The profiler extracts factual information about the dataset.

The LLM should not guess information about the dataset.

Therefore, Python performs the profiling.


The profiler identifies:

1. Number of rows
2. Number of columns
3. Column names
4. Numerical columns
5. Categorical columns
6. Missing values
7. Duplicate rows
8. Descriptive statistics


Example:

Dataset:

PassengerId | Age | Sex | Fare | Survived

The profiler can produce:

Rows:
891

Columns:
5

Numerical:
Age
Fare
Survived
PassengerId

Categorical:
Sex

Missing values:
Age -> 177

etc.


IMPORTANT PRINCIPLE:

Dataset facts should come from Python,
not from the LLM.


Why?

Because an LLM may hallucinate a column.

For example, if the dataset contains:

Age
Sex
Fare

The LLM might incorrectly assume:

Income

exists.

The profiler gives the LLM the actual schema.


============================================================
COMPONENT 3 — PLANNER AGENT
============================================================

File:

agents/planner.py


Purpose:

The Planner Agent converts the user's analytical question
into a sequence of investigation tasks.


Input:

1. User question
2. Dataset profile


Output:

Investigation plan


Example question:

"What factors are associated with passenger survival?"


Planner might generate:

1. Check missing values and data quality.
2. Compare survival rates across categorical variables.
3. Test association between Sex and Survival.
4. Compare Age between survived and non-survived passengers.
5. Analyze the relationship between Fare and Survival.
6. Summarize statistically supported findings.


The Planner does NOT perform the analysis.

It only decides:

WHAT should be investigated?


This separation makes the architecture cleaner.


============================================================
PLANNER PROMPT
============================================================

The Planner is instructed to:

- Create a clear investigation plan.
- Use only available dataset columns.
- Avoid inventing columns.
- Break complex questions into smaller tasks.
- Prefer statistical/data-driven investigations.
- Avoid unnecessary analysis.
- Return numbered investigation tasks.


The Planner receives:

User Question
+
Dataset Profile


and produces:

Investigation Plan


============================================================
WHY DOES THE PLANNER NEED THE DATASET PROFILE?
============================================================

Without the dataset profile, the LLM does not know the available
variables.

Example:

Question:

"What factors affect salary?"

But the dataset contains:

Age
Gender
Department
Experience

and does NOT contain Salary.

A naive LLM might still generate:

"Calculate correlation between experience and salary."

This is invalid.

By giving the dataset profile to the Planner, it can recognize
that Salary is unavailable.


Therefore:

Dataset Profiler
        ↓
Dataset facts
        ↓
Planner


This reduces hallucination.

============================================================
4. HYPOTHESIS TESTING
============================================================

Function:

hypothesis_test()


Currently supports:

Chi-square
Independent t-test
Mann-Whitney U test


------------------------------------------------------------
CHI-SQUARE TEST
------------------------------------------------------------

Used mainly to test association between categorical variables.


Example:

Sex
vs
Survived


Question:

"Is passenger sex associated with survival?"


The tool creates a contingency table and performs:

Chi-square test


Output:

Test statistic
p-value
Degrees of freedom
Sample size


------------------------------------------------------------
T-TEST
------------------------------------------------------------

Used to compare the means of two groups.


Example:

Age

between:

Survived
Not Survived


The implementation uses:

Independent two-sample t-test

with:

equal_var=False


This corresponds to Welch's t-test.


------------------------------------------------------------
MANN-WHITNEY U TEST
------------------------------------------------------------

Non-parametric alternative for comparing two independent groups.


Useful when assumptions for a t-test are not appropriate.


The implementation performs a two-sided test.


============================================================
WHY USE SCIPY?
============================================================

We could ask the LLM to calculate statistics.

That would be a bad design.

For example:

LLM:
"Correlation = 0.73"

But the actual value could be:

0.42

The LLM is not a calculator.

Therefore:

LLM
↓
Decision

Python + SciPy
↓
Calculation

LLM
↓
Interpretation


This is one of the most important design principles of StatAgent.

============================================================
WHY NOT USE LLM-GENERATED PYTHON FOR EVERYTHING?
============================================================

One possible architecture is:

LLM
 ↓
Generate Python code
 ↓
Execute code
 ↓
Result


This is flexible but introduces additional risks:

- Invalid code
- Wrong columns
- Incorrect statistical methods
- Runtime errors
- Security concerns
- Harder debugging


Our current architecture is safer and simpler:

LLM selects from controlled statistical tools.


This is called a controlled-tool approach.


Later, we can introduce a Python executor for analyses that
cannot be handled by the predefined tools.


============================================================
CONTROLLED TOOLS VS FLEXIBLE PYTHON
============================================================

Controlled tools:

Advantages:

- Safer
- Easier to debug
- Predictable
- Easier to validate
- Easier to explain in interviews


Flexible Python executor:

Advantages:

- Much more flexible
- Can handle unusual analytical questions
- Can generate custom visualizations
- Can perform analyses not covered by predefined tools


StatAgent will start with controlled tools.

A Python executor already exists in the planned architecture,
but it will only be used when necessary.


============================================================
IMPORTANT DESIGN PRINCIPLE
============================================================

Never let the LLM invent statistical results.


Correct:

LLM:
"Use chi-square."

Python:
"Chi-square statistic = X,
p-value = Y."

LLM:
"The result provides evidence about association..."


Incorrect:

LLM:
"Chi-square statistic = X."

when Python never calculated X.


The actual evidence must come from deterministic tools.


============================================================
ERROR HANDLING
============================================================

The statistical functions contain validation checks.

Example:

Column 'Income' not found in dataset.


If a t-test is requested but the grouping column contains
more than two groups:

ValueError:
The grouping column must contain exactly two groups.


This is important because agents can make incorrect tool selections.


The future workflow can catch these errors and decide whether
another investigation is required.

============================================================
INTERVIEW QUESTIONS TO KNOW
============================================================

Q1. Why did you use LangGraph?

Answer:

I used LangGraph to manage the multi-step agent workflow and
shared state between different stages such as planning,
investigation, validation and reporting.


Q2. Why not let the LLM perform statistical calculations?

Answer:

LLMs are not reliable numerical calculators. I use the LLM for
reasoning and tool selection while Python and SciPy perform the
actual deterministic calculations.


Q3. Why do you need a dataset profiler?

Answer:

The profiler gives the agent factual information about the
dataset schema, data types, missing values and statistics.
This reduces the chance of the LLM inventing columns or making
unsupported assumptions.


Q4. What is the role of the Planner?

Answer:

The Planner converts the user's analytical question into a
sequence of smaller investigation tasks.


Q5. What is the role of the Investigator?

Answer:

The Investigator determines which statistical method or tool
is appropriate for the current investigation task.


Q6. Why separate Planner and Investigator?

Answer:

The Planner focuses on what should be investigated, while the
Investigator focuses on how a particular task should be analyzed.


Q7. Why use SciPy?

Answer:

SciPy provides reliable implementations of statistical tests
such as chi-square, t-test and Mann-Whitney U, so the numerical
results are calculated deterministically rather than generated
by the LLM.


Q8. What is the difference between Pearson and Spearman
correlation?

Answer:

Pearson measures linear association between numerical variables,
while Spearman measures monotonic association using ranked data.


Q9. What is the chi-square test used for?

Answer:

It can be used to test whether two categorical variables are
statistically associated.


Q10. Does correlation imply causation?

Answer:

No. Correlation indicates statistical association, not necessarily
a causal relationship.


Q11. Why use temperature 0?

Answer:

The agents are performing analytical planning and tool selection,
where predictable outputs are preferred over creative variation.


Q12. What is AgentState?

Answer:

AgentState is the shared memory structure of the LangGraph
workflow. It stores information such as the user question,
dataset profile, investigation tasks, analysis results and
final report.

============================================================
WHY LANGGRAPH?
============================================================

LangChain helps us interact with LLMs and create chains.

LangGraph is used to control a multi-step agent workflow.

Our system contains multiple stages that need to execute in
a specific order and share information.

For example:

The Planner needs:
    User Question + Dataset Profile

The Investigator needs:
    Dataset Profile + Current Task

The Executor needs:
    Investigator Decision + Dataset

Therefore, we need a workflow system that passes information
between these stages.

LangGraph provides this workflow control.

============================================================
INTERVIEW QUESTIONS
============================================================

Q1. Why did you use LangGraph instead of a normal Python
function pipeline?

Answer:

The system contains multiple agentic stages and shared state.
LangGraph allows me to represent these stages as nodes and
control how information flows between them. It will also allow
me to introduce conditional routing and iterative investigation.


Q2. What is a node in LangGraph?

Answer:

A node is a Python function representing one step of the
workflow. In StatAgent, examples include dataset profiling,
planning, investigation and tool execution.


Q3. What is an edge?

Answer:

An edge defines the transition between nodes and determines
which node executes next.


Q4. What is StateGraph?

Answer:

StateGraph allows us to define a graph whose nodes operate on
a shared state object. In StatAgent, the shared state is
AgentState.


Q5. What is the purpose of AgentState?

Answer:

AgentState acts as shared memory between the workflow nodes.
It stores the question, dataset profile, investigation plan,
analysis results, completed tasks and other workflow information.


Q6. Why compile the graph?

Answer:

After defining the nodes and edges, compile() converts the
graph definition into an executable workflow that can be
invoked with an initial state.


Q7. Why didn't you build the loop immediately?

Answer:

I built and tested the workflow incrementally. First I verified
that the individual components could communicate correctly.
Once the linear workflow was working, the next step is to add
conditional routing and iteration.


Q8. How does information move between nodes?

Answer:

Each node receives the current AgentState, performs its operation,
and returns updates to the state. LangGraph passes the updated
state to the next node.


Q9. What is the difference between LangChain and LangGraph
in this project?

Answer:

LangChain is used for LLM interaction, prompts and structured
LLM outputs. LangGraph is used to orchestrate the overall
multi-step agent workflow and state transitions.

============================================================
WHY CURRENT_TASK_INDEX?
============================================================

The Planner produces a list of tasks.

Example:

investigation_plan = [

    "Analyze Sex and Survival",

    "Analyze Passenger Class and Survival",

    "Compare Age between survival groups",

    "Analyze Fare and Survival"

]


We need to know which task the system is currently processing.

Therefore:

current_task_index


is used as a pointer.


Initially:

current_task_index = 0


This means:

investigation_plan[0]


is the current task.


After execution:

current_task_index += 1


Then:

investigation_plan[1]


becomes the next task.

============================================================
CONDITIONAL ROUTING
============================================================

The major LangGraph feature introduced in this step is:

add_conditional_edges()


Instead of always doing:

execute → END


the graph now asks:

"Are there more investigation tasks?"


The router function is:

route_next_task()


It checks:

current_task_index

against:

total number of tasks


Logic:

if current_index < total_tasks:

    return "task"

else:

    return "critic"


============================================================
ROUTER BEHAVIOR
============================================================

Example:

Total tasks = 4


After Task 1:

current_task_index = 1

1 < 4

Therefore:

execute → task


After Task 2:

current_task_index = 2

2 < 4

Therefore:

execute → task


After Task 3:

current_task_index = 3

3 < 4

Therefore:

execute → task


After Task 4:

current_task_index = 4

4 < 4

False.

Therefore:

execute → critic


This creates the investigation loop.


============================================================
LANGGRAPH CONDITIONAL EDGE
============================================================

The graph uses:

builder.add_conditional_edges(
    "execute",
    route_next_task,
    {
        "task": "task",
        "critic": "critic",
    },
)


Meaning:

execute
   ↓
route_next_task()
   |
   ├── "task" → task node
   |
   └── "critic" → critic node


This is an example of conditional routing in LangGraph.


============================================================
WHY CONDITIONAL EDGES ARE IMPORTANT
============================================================

Normal edge:

A → B


means:

Always go from A to B.


Conditional edge:

A → router → B/C


means:

The next node depends on the current state.


This is important for agentic systems because an agent may
need to make decisions about what should happen next.


In StatAgent:

The state determines whether investigation should continue
or move to validation.

============================================================

that the evidence is sufficient.


For example:

Question:

"What factors are associated with passenger survival?"


Suppose only this was completed:

The Critic therefore examines the completed investigation and
provides a sufficiency assessment.


============================================================
CRITIC RESPONSIBILITY
============================================================

The Critic answers:

"Do the collected analyses provide enough evidence to answer
the user's question?"


It does NOT answer:

"What is the statistical result?"

because Python/SciPy already calculates the statistical result.


It also does NOT invent new evidence.


Its responsibility is validation and coverage.

============================================================
INTERVIEW QUESTIONS
============================================================

Q1. Why did you introduce a loop?

Answer:

The Planner can generate multiple investigation tasks.
Initially the workflow only executed the first task. I added
a task index and LangGraph conditional routing so the system
can automatically process each task until the investigation
plan is completed.


Q2. How does the system know when to stop?

Answer:

The current task index is compared with the total number of
tasks in the investigation plan. If more tasks remain, the
graph routes back to the Task node. Otherwise it routes to
the Critic.


Q3. What is conditional routing in LangGraph?

Answer:

Conditional routing allows the next node to depend on the
current state. In StatAgent, the router determines whether
to investigate another task or move to the Critic.


Q4. Why do you need a Critic Agent?

Answer:

The Critic evaluates whether the collected evidence is
sufficient to address the original question. It acts as a
validation stage before generating the final report.


Q5. Does the Critic perform statistical calculations?

Answer:

No. Statistical calculations are performed by deterministic
Python and SciPy tools. The Critic only evaluates the
collected evidence.


Q6. What does the Critic receive?

Answer:

It receives the original question, investigation plan,
completed tasks and statistical analysis results.


Q7. Why use structured output for the Critic?

Answer:

The workflow needs predictable fields such as
evidence_sufficient and feedback. Structured output makes
the LLM response machine-readable and easier to use inside
the LangGraph workflow.

Q1. What is the purpose of the Final Report Agent?

Answer:

The Final Report Agent converts the statistical evidence
collected during the investigation into a structured,
human-readable analytical report.


Q2. Does the Report Agent perform statistical calculations?

Answer:

No. Statistical calculations are performed deterministically
using Python and SciPy. The Report Agent only interprets and
communicates the results.


Q3. What information does the Report Agent receive?

Answer:

It receives the user's question, investigation plan, completed
tasks, statistical analysis results and Critic feedback.


Q4. Why separate the Critic and Report Agent?

Answer:

The Critic validates whether the evidence is sufficient, while
the Report Agent communicates the validated evidence to the
user. This keeps the responsibilities separate.


Q5. How do you prevent the LLM from hallucinating statistical
results?

Answer:

The statistical values are generated by deterministic Python
and SciPy tools. The Report Agent is instructed to use only
those results and not perform new calculations or invent
evidence.


Q6. What happens after the Report Agent?

Answer:

The generated report is stored in AgentState as final_report
and the LangGraph workflow reaches END.
